# Security policy

Framejury is a personal tool that runs on one computer for one person, and it handles photos that often belong to someone else, so a security problem here usually means that private images or the names of private files could be exposed, and for that reason reports are taken seriously.

## Supported versions

Only the latest code on the `main` branch receives fixes, because the project is young and does not publish separate release lines.

## How to report a vulnerability

Please do not open a public issue for a security problem. Use the private reporting option of GitHub instead, which you can find in the Security tab of the repository under the button called Report a vulnerability, so that the details reach the maintainer without becoming visible to everyone before a fix exists.

A useful report explains what you found, the steps needed to reproduce it, the version or commit where you saw it and the effect you believe it could have. Please do not attach photos that belong to other people, because a description or a generated test image is always enough to show the problem.

You can expect a first answer within about a week, since this is a project maintained by one person, and the fix will be credited to you in the commit history unless you prefer to stay anonymous.

## What is in scope

The following areas are the ones that matter most for this project.

The engine should only accept requests that come from the local interface, so any way of making it answer to another host name, to another website or to another device on the network is in scope. Reading or writing files outside the folder that the user chose, including through thumbnail requests, exports or sidecar files, is in scope as well. Anything that makes Framejury send photos or their metadata to a server on the internet is in scope and would be treated as a serious problem, and the same applies to any path that lets text inside a photo or a file name change what the program does beyond the ranking inside a group.

## What is out of scope

Some situations come from how the tool is meant to be used and are not considered vulnerabilities. Starting the engine with a host other than `127.0.0.1`, or exposing port 8000 to a network, goes against the instructions in the README, and the absence of a login is a deliberate choice for a single trusted user. A wrong judgment from the language model, such as missing a pair of closed eyes, is a quality problem and not a security problem, and it can be reported as a normal issue. Weaknesses in Ollama, in the model itself or in the third party packages that Framejury depends on should be reported to their own maintainers, although a note here about how they affect Framejury is welcome.

## Handling your own data

Reports generated by Framejury are stored in the `data` folder next to the engine and contain the paths and names of the analyzed photos, so they should be deleted when a job is finished and never committed to a repository. The `.gitignore` file of this project already excludes them, and it is worth checking that your own copy does the same.
